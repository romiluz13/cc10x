## Differences From Agreement
Items where this plan departs from the design file's outline; each is flagged for the user at plan review.
1. **Eval moved before router edits.** Design outline order is 3 router, 4 hooks, 5 docs, 6 eval, 7 split. This plan runs the behavioral eval harness and baseline as Phase 3, before the router edits in Phase 4, so the largest prompt change is measured, not just string-pinned. The requirement "eval before the split" still holds and is re-checked as the Phase 7 go/no-go.
2. **Health check is shell-first.** Design says "stdlib-only SessionStart health check". A Python script cannot report that Python cannot start (hooks that cannot start exit like 127 and the action proceeds, hooks reference). The preflight is a POSIX `sh` script (`scripts/cc10x_preflight.sh`) that probes `python3` and emits `additionalContext`.
3. **Archive directory is `docs/history/`**, not an "archive" path (gitignore shadowing, ASM-8).
4. **Status-line surfaces may drop from 5 to 3.** If checkpoint C6.1 archives the orchestration bible and logic-analysis (D3), the version status line is required only in `router-invariants.md`, `prompt-invariants.md`, `agent-contract-registry.md`; the release phase uses `harness_audit` output as the authoritative surface list.
5. **Marketplace version surfaces may drop from 3 to 2** (RD-7).
6. **One extra finding (N1)** was found while planning and is included (hook logger flags non-cc10x subagents as `contract_missing`).
7. **qa-researcher part of A2 is downgraded to "verify first"**: `agents/qa-researcher.md:63-64` names Jira/Confluence as source types, not MCP tools.
8. **P4 checkpoints C4.1-C4.3 all move to the start of P4** (revision 2): every one of them can change `SKILL.md` or the policy reference, and `SKILL.md` has exactly three sequential edit tasks (P4.T1.5a-c).

## Critical-Path Specification (required for `critical_path`)

### Behavior contract
- **Hooks (P1, P5):** every registered hook command, given any documented event payload (including `{}`) on stdin, exits 0 or 2, never emits a traceback, and never raises on malformed JSON. Exit 2 appears only where the platform defines blocking (PreToolUse deny) or feedback (PostToolUse stderr to the model; the write already happened). Fail-open on non-0/2 exits is accepted platform behavior, made visible by the preflight and logs.
- **Preflight:** emits `additionalContext` iff `python3` is missing or older than 3.9; silent otherwise; exit 0 always.
- **Hook-mode resolution:** total function over (shipped file, user override, defaults); output always has `artifactIntegrity`, `memoryWrites`, `taskMetadata`, each `block|audit`.
- **Git guard:** deny the destructive set, allow quoted data and safe commands, keep the single-use token only for remote publish and branch force-delete.
- **Agent delivery:** every `skills:` entry in an agent resolves and is invocable by Claude; `agent-common` demonstrably preloads for the 13 agents.
- **Router gates:** the REM-FIX gate fields each have exactly one producer; each workflow's reference is reachable by name from `SKILL.md`; Memory Update runs once per workflow.
- **Split (P7):** text moves, semantics do not; L1 and L2 results do not regress.

## Architecture Decision Records
### ADR-1: Eval before router edits
**Context:** string pins (253) cannot detect behavior regressions; P4 is the largest prompt change. **Decision:** build L1 fixtures and an L2 eval baseline in P3, with known-red cases that encode defects P4 fixes. **Rejected:** (a) eval after P4 (design outline) because P4 would be unmeasured; (b) no L2, L1 only, because L1 validates shape not behavior (kept as the fallback). **Consequences:** P3 costs model spend and adds a go/no-go; P4 gets TDD-style red/green flips. **Reversibility:** reversible.
### ADR-2: Shell-first preflight, fail-open hooks stay fail-open
**Context:** a Python check cannot report a missing interpreter; non-0/2 exits proceed by platform design. **Decision:** `sh` preflight emitting `additionalContext`; no wrapper changes. **Rejected:** fail-closed wrapper (`python3 x.py || exit 2`) because a missing or broken interpreter would block every Bash and edit call; requiring Python 3.10+ (design ADR note). **Consequences:** guards can still fail open on a broken interpreter, now visibly. **Reversibility:** reversible.
### ADR-3: Docs-rot ratchet instead of red validators
**Context:** new validators would fail at HEAD against rotten docs, but phases must end green. **Decision:** a baseline file that may only shrink, empty at release. **Rejected:** failing gate until P6 (violates "no phase starts on a red gate"); allow-lists without ratchet (rot hides). **Consequences:** one extra file and about 40 lines in `harness_audit.py`. **Reversibility:** reversible.
### ADR-4: `docs/history/` for archives
**Context:** `.gitignore` shadows `archive/` and `*-PLAN.md`. **Decision:** `docs/history/` plus `!docs/history/*.md`, verified per path. **Rejected:** `docs/archive/` (silently untracked, the recurring gitignore-shadowing failure); deleting history (user decision 2). **Reversibility:** reversible.
### ADR-5: One gate runner
**Context:** the gate list lived in a memory file; plain pytest is vacuous for three of four test files. **Decision:** `release_gate.py` plus a documented section. **Rejected:** docs only (drifts again); a Makefile (new toolchain). **Consequences:** one stdlib file (about 100 lines). **Reversibility:** reversible (RD-1).
